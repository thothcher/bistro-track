Solution 1 The pantry

A store lives outside React

Not a component

The store is a plain module: one object that holds the state and the actions. React does not own it, so it does not re-render it.

A selector is a question

A component subscribes with a small function: "how many Espressos are in the order?" No provider is needed.

Only changed answers render

After a change the store asks every selector again. Two answers changed, so two components render.

Do: One press per idea. Step 1: the store appears outside the dashed tree. Step 2: four wires, one per subscriber, each with the question it asks. Step 3: a click on the Espresso card sends add to the store. Step 4: the store asks the four questions again; only Header and Espresso get a different answer.

Say: Compare with the pass from last time: the pass was a component that wrapped the tree and woke every reader. The pantry is outside the tree and wakes only the readers whose answer changed.

Remember: "outside React" is also why you can call it from api.ts, from a test, from a timer. We use that in the second half.

Solution 1 What a store is made of

Four ideas in one file

export const useCartStore = create<CartState>()( (set) => ({ items: [], add: (dish) => set((s) => ({ items: [...s.items, dish] })), }), ); const qty = useCartStore((s) => s.items.length);
01

create()
Builds the store and returns a hook. The second pair of parentheses is not a typo: it is how TypeScript learns the state type.

02

items: []
The state: plain data, here the cart. Nothing special, no hook.

03

add: … set(…)
Actions live in the store. set merges what you give it into the state, like a mini setState.

04

useCartStore(selector)
The hook the store gives back. The selector picks one piece; the component re-renders only when that piece changes.

Say: That is all of Zustand's core. Create a store, put state and actions in it, read it with a selector. Everything else (persist, devtools) is an add-on.

If asked "why not Redux?": next lecture slide. Short answer: same idea, less ceremony.

Solution 1 The same hook is also an object

A store works outside React

IN A COMPONENT

The hook subscribes. The component re-renders when the answer changes.

ANYWHERE ELSE

getState() reads once and subscribes to nothing. For api.ts, a timer, a test. Never for the screen.

WATCH IT

subscribe() runs a function on every change. In L34 it empties a cache when the guest signs out.

One rule: the screen uses the hook, everything else may use the object.

A component that reads getState() in its body shows a number that never updates. That mistake is on the next slide.

Say: A context cannot do this: it exists only inside the tree, so api.ts could never read the session. A store is a plain object with a hook on top.

Preview: in the second half api.ts signs the guest out by itself when the token expires. That is getState().logout().

Solution 1 The four mistakes you will see today

When a store goes wrong

A selector that builds an object

useCartStore((s) => ({ count: s.items.length }))
The result of getSnapshot should be cached to avoid an infinite loop · Maximum update depth exceeded
useCartStore((s) => s.items.length), or wrap it in useShallow

No selector at all

const { items, add } = useCartStore();
No error. It works, and re-renders on every change of anything.
const add = useCartStore((s) => s.add);

Changing the state in place

set((s) => { s.items.push(dish); return s; })
Nothing happens on screen: the same object, so no re-render.
set((s) => ({ items: [...s.items, line] })), or the reducer

getState() in a component

const count = useCartStore.getState().items.length;
The number never updates: getState() reads once and subscribes to nothing.
const count = useCartStore((s) => s.items.length);

Say: The first one is the loudest and the others are silent. Silent bugs are the dangerous ones: number 2 is the reason we started the lecture.

Mistake 1: a selector must return the same value for the same state. A new object is a new value every time, so React sees a change on every check and loops.
