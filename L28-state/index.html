What does key do in a list?

It gives each item a stable name, so React can tell the items apart when the list changes. Use the id, never the index.

Problem 1 What really happens

Why the screen doesn't change

1

React drew the button once

It called DishCard(), got JSX with qty = 0, and put it on the page. Then it waits.

2

Nobody told React

Changing a local variable is invisible to React. It has no reason to call DishCard() again.

3

Even if it did…

…the function would start from the top: let qty = 0. The count would be lost.

Say: A component is a function. React calls it to get the picture of the page. Between calls, local variables don't survive, and React only calls it again when it is told something changed.

Solution 1 The errors you will see today

When state goes wrong

Calling the setter while rendering

onClick={setQty(qty + 1)}
Too many re-renders. React limits the number of renders to prevent an infinite loop.
onClick={() => setQty(qty + 1)}

Changing the variable directly

qty = qty + 1; // or qty++
TypeScript: Cannot assign to 'qty' because it is a constant. The screen never updates.
setQty(qty + 1);

A hook inside an if

if (dish.isAvailable) { const [qty, setQty] = useState(0); }
React Hook "useState" is called conditionally.
const [qty, setQty] = useState(0); // top of the component

Reading state right after setting it

setQty(qty + 1); console.log(qty); // still the old value
Not an error: the snapshot. The new value arrives in the next render.
const next = qty + 1; setQty(next); console.log(next);

Say: Number 1 is the classic. Number 4 is not a bug in React, it is the snapshot from three slides ago.

Solution 2 Why we never change state in place

A new box, not the same box

Change the old array

=== box #1
React: "same box as before, nothing changed." No re-render.

Make a new array

React: "a new box!" Re-render.
To…Don'tDo

Solution 2 The rule of derived state

Don't store what you can calculate

Store the minimum

If a value can be computed from state or props, compute it during render. Storing it twice means one day the two copies disagree.

Say: Three pieces of state, everything else is calculated. A count state next to cart would be a bug waiting to happen: someone updates one and forgets the other.

When lifting goes wrong

Push, then set the same array
