Solution 1 What a component is made of

A component is a function that returns UI

export function Header() { return ( <header className="site-header">…</header> ); }
01

export
Other files may import it. Forget it and App cannot see the component.

02

Header
A capital letter. That is how React tells your component from an HTML tag.

03

return ( … )
What the component shows. React calls the function and puts the result on the page.

04

<header>
JSX: HTML-like markup inside JavaScript. Exactly one root element.

Say: No new magic: a component is a plain JavaScript function. Its name starts with a capital letter and it returns JSX.

Do: One press per part. Each card lights its piece of code.

If asked "what is JSX?": markup written inside JavaScript. The build tool (Vite) turns it into normal function calls. The browser never sees JSX.

Solution 1 JSX looks like HTML, with six differences

Six JSX rules

1. className

<div class="card">
<div className="card">

2. Close every tag

<img src={src}>
<img src={src} />

3. One parent

return <h1/><p/>
return <><h1/><p/></>

4. Braces for JavaScript

<p>dish.name</p>
<p>{dish.name}</p>

5. camelCase attributes

onclick for tabindex
onClick htmlFor tabIndex

6. Comments in braces

<!-- the menu -->
{/* the menu */}

Do: One rule per press. Read the red line, ask what is wrong, then read the green line.

Rule 3: <>…</> is a "fragment": a parent that adds no element to the page.

Rule 4: braces mean "this is JavaScript, put its value here". Without braces it is plain text.

Solution 2 The rule of the tree

Props flow down

Parent → child

A parent passes data to its children as props. App passes the list, DishGrid passes one dish to each card.

Read-only

A child never changes its props. dish.price = 0 inside DishCard is a bug. (Changing data is lecture L28.)

Solution 2 The props errors you will see today

When props go wrong

A number in quotes

<Price value="32" />
Type 'string' is not assignable to type 'number'.
<Price value={32} />

No key in a list

dishes.map((dish) => <DishCard dish={dish} />)
Each child in a list should have a unique "key" prop.
<DishCard key={dish.id} dish={dish} />

Forgot the braces in the parameters

function DishCard(dish: DishCardProps)
dish.name is undefined (the dish is in dish.dish)
function DishCard({ dish }: DishCardProps)

A missing prop

<DishGrid />
Property 'dishes' is missing in type '{}' but required in type 'DishGridProps'.
<DishGrid dishes={dishes} />

Say: Two of these are caught by TypeScript before you even save (1 and 4). The key warning appears in the browser console. Number 3 shows an empty card: check the parameters.

Which line passes the number 32?

Quotes pass text. Braces pass any JavaScript value: numbers, booleans, objects, functions. C and D do not compile.
