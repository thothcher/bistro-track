Apéritif Before we start

Questions from last time?

useState, lifting state, new arrays, derived values.

01

Why [...cart, item] and not cart.push(item)?

React compares old and new state with ===. A pushed array is the same array, so React sees no change.

02

Where does state live when two components need it?

In their closest common parent. Data goes down as props, events come up as functions.

03

Should the cart total be state?

No. It is derived from the cart: calculate it during render.

Plat · Solution 1 The tool

useEffect: code that runs after the render

useEffect(() => { // talk to the outside world return () => { /* clean up */ }; }, [dependencies]);
01 · the effect

Runs after React has put the render on the screen. Fetch, timers, listeners, localStorage live here.

02 · the cleanup

Optional. Runs before the effect runs again, and when the component leaves the page.

03 · the dependencies

When to run it again: after any render in which one of these values changed.

Say: React's job is to turn data into UI. Everything else (the network, timers, the browser's storage, keyboard listeners) is "the outside world". useEffect is the door to it.

Remember: effects run after the screen is updated, so the user sees something (a skeleton) while we wait.

Solution 1 When does the effect run again?

The dependency array decides

You writeIt runsUse it for
useEffect(fn, [])once, after the first rendera keyboard listener, a page view
useEffect(fn, [category])after the first render, and whenever category changesfetching the dishes of a category
useEffect(fn)after every renderalmost never. With a setState inside: an endless loop

The rule: list every value from the component that the effect uses.

The linter (eslint-plugin-react-hooks) checks it for you: "React Hook useEffect has a missing dependency".

Solution 1 The first real request fails

CORS: the server only talks to friends

Browserlocalhost:5173
Le Bistro APIsrmsapi.stepacademy.ge
Vite dev serverthe same address as the page
Console
Access to fetch at 'https://srmsapi.stepacademy.ge/api/v1/…' from origin 'http://localhost:5173' has been blocked by CORS policy

Now fetch the relative path: fetch("/api/v1/enterprise/dishes"). Restart npm run dev after editing the config.

Say: The browser asks the server: "may this page read your answer?" The Le Bistro API answers yes only for its own site (and localhost:4200). Our localhost:5173 is not on its list, so the browser blocks the answer. That's CORS: a browser rule, not a React rule.

The fix: Vite's proxy. The page asks its own server for /api/…, Vite forwards it to the real API. Servers don't have CORS. In production, vercel.json does the same (lecture L30).

Students' DummyJSON allows every origin, so they won't hit this. Le Bistro does, on purpose.

Solution 1 Don't panic

"Why do I see two requests?"

In development, <StrictMode> runs every effect twice on purpose: effect, cleanup, effect.

It's a test, not a bug

If your effect has a correct cleanup, the user can't tell the difference. In production (npm run build) it runs once.

Say: students WILL ask this. StrictMode (in main.tsx) double-runs effects in development to catch effects that forget to clean up. Never remove StrictMode to "fix" it.

Solution 1 The errors you will see today

When effects go wrong

An async effect function

useEffect(async () => { … }, []);
Effect callbacks are synchronous to prevent race conditions. Put the async function inside.
useEffect(() => { fetch(…).then(…); }, []);

A missing dependency

useEffect(() => { load(category); }, []);
React Hook useEffect has a missing dependency: 'category'.
useEffect(() => { load(category); }, [category]);

An object created during render as a dependency

const filter = { category }; useEffect(…, [filter]); // new object every render
The effect runs after every render: a loop of requests.
useEffect(…, [category]); // a string compares by value

Trusting fetch with errors

fetch(url).then((res) => res.json())
A 404 or 500 still "succeeds": res.json() then fails with an unclear error.
if (!res.ok) throw new Error(`HTTP ${res.status}`);

Quick check The dependency array

This effect loads the dishes of the selected category. Which array?

The effect uses category, so it must run again when category changes. [] loads only the first category. [dishes] loops (the effect changes dishes). No array runs after every render: a loop too.

Solution 2 · Recipe The cleanup cancels, the tag protects

Cancel the old request

  1. One AbortController per runA remote control for one fetch.
  2. Give fetch its signalSo the controller can stop it.
  3. The cleanup abortsRuns before the next effect: the old request dies.
  4. Ignore our own cancelAn aborted fetch rejects. That's not an error to show.
  5. Tag the answer with its requestShow data only if it belongs to the current path. loading is derived.

Say: two protections. The AbortController stops the old request (saves the network). The tag makes sure an old answer that slipped through can never be shown under a new chip.

Solution 2 The last hook of the day

useRef: press "/" to search

  1. A ref is a box React doesn't watchChange ref.current and nothing re-renders. Here it holds the real <input>.SearchBox.tsx
  2. Attach itref={inputRef}: React puts the DOM element in the box.
  3. Listen to the keyboardA listener on window is the outside world: an effect.
  4. Remove it in the cleanupOr every StrictMode remount adds a second listener.

Say: useState is a box React watches: change it and the component renders. useRef is a box React ignores: perfect for DOM elements, timers, anything the screen doesn't show.

Rule: read refs in event handlers and effects, not while rendering.

Solution 2 The most important warning of today

You might not need an effect

An effect to calculate

Two renders instead of one, a second copy of the data, and a lint error: "set-state-in-effect".

Just calculate it

Derived value, from L28. One render, one truth.

Effects are for the outside world: the network, timers, the browser, the keyboard.

If you only transform props or state, you don't need one.

Solution 2 The bugs of the second half

When hooks go wrong

A listener without cleanup

useEffect(() => { window.addEventListener("keydown", f); }, []);
Two listeners after StrictMode, more after every remount. "/" focuses twice.
return () => window.removeEventListener("keydown", f);

A hook inside an if or a loop

if (searching) { const results = useApi(path); }
React Hook "useApi" is called conditionally.
const results = useApi(searching ? path : null);

A timer that is never cleared

useEffect(() => { setTimeout(…, 400); }, [value]);
Every keystroke still fires: no debounce at all.
const t = setTimeout(…); return () => clearTimeout(t);

Reading a ref while rendering

return <p>{inputRef.current?.value}</p>;
Shows stale values: refs don't trigger renders.
Use state for anything the screen shows.

Quick check Effect or not?

Which one needs useEffect?

A, B and D are calculations: derive them during render. localStorage is outside React: writing to it is a side effect.
